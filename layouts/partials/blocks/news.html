{{- /* Lab News block: renders `data/news.yaml` as a compact dated list. Used twice, with different options: - the homepage (`content/_index.md`): the ten newest items plus an "All news" link to the archive - the archive (`content/news/_index.md`): every item, grouped by year Block options, all under `content:` in the page's front matter: title Section heading. `news` is not one of the block types that `functions/parse_block_v2.html` injects a heading for, so this partial prints its own, with the same markup the markdown blocks get. That way `section-title-left-aligned` and the other heading styles apply unchanged. subtitle Optional line under the heading. count How many items to show. 0, the default, shows them all. group_by_year true prints a year heading above each year's items. archive_link URL of the full list. The "All news" link appears only when `count` actually hides some items. Order: newest month first. Items from the same month keep the order they have in the data file. Rather than trust the sort to be stable, each item's sort key carries its file position as a tie-breaker, so the result is the same whatever the sort algorithm does with equal keys. Bad data fails the build with a message naming the entry. That shows up in `hugo server` locally and in the deploy build (publish.yaml), which then stops and leaves the live site as it was, instead of publishing a silently wrong row. No pull-request check builds the site. */ -}} {{- $page := .wcPage -}} {{- $block := .wcBlock -}} {{- $section_id := .wcIdentifier -}} {{- $count := int ($block.content.count | default 0) -}} {{- $group_by_year := $block.content.group_by_year | default false -}} {{- $archive_link := $block.content.archive_link | default "" -}} {{- /* One Font Awesome icon per news type.
